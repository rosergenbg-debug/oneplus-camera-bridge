# OnePlus Camera Bridge 0.1.0

Небольшой диагностический Android‑мост для проверки цепочки:

`стороннее приложение → ACTION_IMAGE_CAPTURE → OnePlus Camera → JPEG → стороннее приложение`.

MVP не перехватывает Camera2/CameraX и не обещает работать с приложениями, которые рисуют собственный интерфейс камеры. Он работает только тогда, когда исходное приложение просит Android найти обработчик стандартного `MediaStore.ACTION_IMAGE_CAPTURE`.

## Что реализовано

- Kotlin, `minSdk 30`, `compileSdk/targetSdk 36` (Android 16), Material 3.
- `MainActivity`, которая всегда остаётся доступной.
- Отключаемая `CaptureProxyActivity` для `IMAGE_CAPTURE` и `IMAGE_CAPTURE_SECURE`.
- Явный запуск выбранного компонента внешней камеры и тройная защита от рекурсии:
  - собственный пакет исключается из результатов поиска;
  - камера запускается через точный `ComponentName`;
  - внутренний extra `bridge_internal_request=true` блокирует повторный вход в мост.
- Временный JPEG только в приватном `cacheDir/camera_bridge`.
- `FileProvider`, `ClipData`, временные разрешения чтения/записи.
- Проверка результата: `RESULT_OK`, ненулевой файл, JPEG, размеры и минимально разумное разрешение.
- Копирование готового JPEG в `content://` вызывающего приложения.
- Запасной уменьшенный Bitmap (не более 384 px по стороне), если `EXTRA_OUTPUT` отсутствует.
- Чтение EXIF без перекодирования оригинального JPEG: модель, дата, orientation.
- Поворот только экранной миниатюры; оригинальный JPEG не изменяется.
- Локальный журнал до 100 текстовых событий с копированием в буфер обмена.
- Очистка временных файлов после успеха, отмены, ошибки и при следующем запуске (старше часа, кроме отмеченной незавершённой операции).
- Аварийное отключение компонента, сброс камеры и очистка временных данных.
- Открытие стандартной страницы Android для ручного удаления приложения.

В манифесте намеренно нет `INTERNET`, `CAMERA`, фоновых служб, ресивера загрузки, Accessibility Service, Device Administrator или доступа к общим файлам. Разрешение `CAMERA` мосту не требуется: фотографирует отдельное штатное приложение камеры.

## Структура

- `MainActivity` — управление, выбор камеры, внутренний тест, очистка и отключение.
- `CaptureProxyActivity` — приём запроса, запуск камеры, проверка и возврат результата.
- `LogActivity` — диагностический журнал.
- `CameraDiscovery` — поиск, исключение собственного пакета и эвристическое ранжирование системной камеры.
- `ImageUtils` — проверка JPEG, EXIF и безопасная миниатюра.
- `TempFiles` — жизненный цикл временных файлов.

## Сборка в Android Studio

1. Установите актуальную Android Studio с JDK 17.
2. В SDK Manager установите Android SDK Platform 36 и Android SDK Build‑Tools 36.x.
3. Откройте папку `oneplus-camera-bridge`.
4. Дождитесь Gradle Sync.
5. Выберите **Build → Build APK(s)**.
6. APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

Проект использует Android Gradle Plugin 8.13.2, Gradle 8.13 и JDK 17. Если Android Studio попросит создать/обновить Gradle Wrapper, согласитесь на Gradle 8.13. Исходники не требуют NDK.

Командная сборка при установленном Gradle 8.13 и настроенном `ANDROID_HOME`:

```bash
gradle :app:assembleDebug
```

## Установка через ADB

Включите на телефоне «Для разработчиков → Отладка по USB», подтвердите доверие компьютеру и выполните:

```bash
adb devices
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Удаление через ADB, если оно когда-либо понадобится:

```bash
adb uninstall de.rosberg.onepluscamerabridge
```

Обычный предпочтительный способ удаления — кнопка в приложении, открывающая системную страницу сведений, затем стандартная кнопка «Удалить».

## Проверка на OnePlus 15

1. Установите debug APK.
2. Откройте **OnePlus Camera Bridge**.
3. Убедитесь, что показан статус «Перехватчик внешней камеры включён».
4. Нажмите «Показать найденные приложения камер».
5. Нажмите «Выбрать штатную камеру» и выберите системную OnePlus Camera. Системные обработчики отмечены в списке; наиболее вероятная камера стоит первой.
6. Нажмите «Проверить камеру», сделайте настоящий снимок штатной кнопкой затвора и подтвердите его.
7. Проверьте разрешение, размер JPEG, EXIF и миниатюру. Нажмите «Закрыть и удалить снимок».
8. По очереди проверьте камеру/вложение в WhatsApp, ChatGPT, Telegram, eBay, браузерной форме и системном выборе вложений.
9. После каждого теста откройте журнал и скопируйте его. Журнал покажет, запускался ли мост, наличие `EXTRA_OUTPUT`, выбранную камеру, размер результата и ошибку передачи.

Ожидаемая классификация результата:

- мост появился среди вариантов или открылся напрямую — приложение использует `ACTION_IMAGE_CAPTURE`, цепочка потенциально совместима;
- сразу открылся собственный экран камеры приложения и в журнале нет нового входящего события — приложение использует внутренний Camera2/CameraX‑модуль; перехват обычным APK невозможен;
- открылся системный Photo Picker/галерея — это выбор существующего файла, а не запрос на создание фотографии;
- мост открылся, но запись в URI не удалась — смотрите `SecurityException`/URI в журнале; вызывающее приложение могло не выдать корректное временное разрешение.

## Получение реального списка пакетов камер

До запуска на конкретном OnePlus 15 реальный пакет штатной камеры определить нельзя: имя зависит от OxygenOS/региона/обновления. Самый надёжный список создаёт кнопка «Показать найденные приложения камер» и записывает его в журнал.

Дополнительная проверка через ADB:

```bash
adb shell cmd package query-activities -a android.media.action.IMAGE_CAPTURE -c android.intent.category.DEFAULT
adb shell cmd package resolve-activity --brief -a android.media.action.IMAGE_CAPTURE
```

В отчёт после теста нужно вставить полные `package/class` из журнала. Не следует заранее жёстко прописывать предполагаемый пакет OnePlus Camera.

## Известные ограничения MVP

- Нельзя перехватить прямой доступ другого приложения к Camera2 или CameraX без root/инъекции/Accessibility; такие обходы здесь намеренно отсутствуют.
- Android сам решает, показывать ли выбор обработчика `ACTION_IMAGE_CAPTURE`. Если пользователь ранее назначил другую камеру «Всегда», сначала сбросьте её настройки по умолчанию в Android.
- Некоторые OEM‑камеры игнорируют `EXTRA_OUTPUT`, возвращают только миниатюру или отказываются работать с URI стороннего `FileProvider`. В таком случае журнал честно покажет пустой файл/ошибку.
- `IMAGE_CAPTURE_SECURE` зависит от политики экрана блокировки и конкретной OEM‑камеры. Мост не обходит блокировку и не ослабляет защищённый режим.
- `callingPackage` нередко равен `null` из‑за способа запуска Activity; тогда используются `callingActivity` и `referrer`, но они тоже не гарантированы Android.
- Эвристика системной камеры — это ранжирование по системному флагу, словам `camera`, `oneplus`, `oplus`, `coloros`; окончательный выбор делает пользователь.
- Внешнее приложение может отвергнуть результат даже после успешного стандартного возврата, если ожидает собственный нестандартный протокол.
- Тесты реальной фирменной обработки HDR/мультикадровой съёмки возможны только на телефоне: мост не может доказать, какие внутренние алгоритмы применила закрытая камера. EXIF, разрешение и визуальное сравнение дают косвенные признаки.

## Безопасность и удаление

Все фото находятся только в приватном кэше приложения и не добавляются в MediaStore/галерею. При аварийном завершении незавершённый путь помечается локально; при следующем запуске бесхозные файлы старше часа удаляются. «Аварийно отключить мост» отключает только `CaptureProxyActivity`, сбрасывает предпочтительную камеру и удаляет весь временный кэш. `MainActivity` остаётся доступной.

Стандартное удаление Android удаляет APK, приватный кэш, настройки и журнал. Постоянных служб и общих файлов приложение не создаёт.
